## Verified regression found during this review

A successful `docker create` that pulls its image therefore returns pull progress plus its container ID. The validator passes that whole string as one resource identifier to `inspect` and `rm`. The removal fails with `page not found`, bypassing the sentinel assertion, inventory export and final resource checks.

This is independently reproduced through `scripts/validate fullDocker --scenario network` with an uncached pinned platform reference, without deleting any cached image. All 12 network assertions passed before cleanup failed. The reviewer inspected the exact owned sentinel label, removed that sentinel by its unique name, and confirmed the deployment's containers, networks and volumes were absent. ## Derived backup image and new risks

The Dockerfile-specific ignore file excludes everything except the Dockerfile and its ignore file. Three actual Docker builds using that exact ignore file failed to copy benign world, backup-repository and generated-secret canaries because those paths were absent from the context. No real secret was printed. [Context probes](context-probes.json).

A fresh deployment completed its initial scheduled snapshot and a manual snapshot. Changing only `BACKUP_IMAGE` from the current index digest to its pinned ARM64 child digest changed the effective derived tag even though `settings.env` retained the original tag. Public `start` built/selected that new tag and recreated the sidecar. The resulting image's layers matched the selected base plus the single patch layer. A manual backup then succeeded. Changing the base to the pinned NGINX image made the public build fail the script patch guard. These are real config/start/build operations, not calculations of what a tag should be. [Reproduction](pin-final-events.json), [events](pin-final-events.json), [13 passing boundary assertions](pin-final-assertions.json).

The changed base reference intentionally selects the same platform software contents through a different digest identity. It proves stale generated settings cannot select the old derived identity. It does not certify an arbitrary future upstream backup version; the exact patch guard and a repeated full gate remain necessary for such an update.

Exploratory failures are retained rather than hidden. One check assumed a BuildKit-fetched digest would already be available to Docker image inspect; an explicit pull corrected that inspection. Another expected one remaining textual save-on statement; the actual patched script correctly retains two other statements. An early interrupted fixture later reported repository integrity errors. No cause was established and no source bug is asserted from that fixture. The fresh completed-initial-snapshot transition passed, including another manual snapshot.
