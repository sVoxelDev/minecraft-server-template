## Template inspection

Inspected the README, every Compose fragment, shell scripts, environment files, server and proxy configs, plugin configs, database config, download web config, Gradle helper, ignore rules and tracked file inventory. The bundled Dynmap directory contains old static JavaScript and PHP assets; those assets were inventoried, not subjected to a full vulnerability audit. No automated startup or runtime validation entry point, test suite or CI workflow is present.

- `dc.sh` indiscriminately combines every `docker-compose.*.yml` except minimal, in `find` order. Database, backup, public web services, RCON UI and proxy are mandatory together. Both main and minimal depend on DB. There is no standalone Paper selection or safe explicit optional-service interface. Arguments use unquoted `$@` and a string of file arguments, so spaces in checkout paths are unsafe. Helpers resolve files from the caller's current directory.
- `globals.env` pins Minecraft 1.17.1 and sets `EULA=true` and `ONLINE_MODE=false`. `server-properties.env` also sets offline mode. Minimal publishes game port 25565 and unauthenticated JDWP on 5005 to all host interfaces. Its phpMyAdmin publishes 8080 and receives database login credentials. Main does not publish its game TCP port, but all services share the same network.
- `configs/proxy/config.yml`, `modules.yml`, `waterfall.yml` and `locations.yml` are Bungee/Waterfall formats. Proxy defaults to WATERFALL and online authentication. Main enables `settings.bungeecord` in Spigot; legacy `paper.yml` has Velocity disabled and an empty forwarding secret. There is no `velocity.toml` or modern forwarding secret wiring. Merely changing `PROXY_TYPE` cannot turn these configs into a working Velocity configuration.
- The setup's query answer becomes `STATUS_PORT`, which no Compose fragment uses. Main publishes UDP using `QUERY_PORT` default 25575, while the proxy config listens for query on 25577. No matching end-to-end query configuration is established.
- `set_rcon_pw` generates an unused local RCON password and only writes the RCON UI login password. No `RCON_PASSWORD` is configured for Paper. `rcon.env` commits `RWA_RCON_PASSWORD=minecraft`. Matching runtime credentials and protection therefore depend on image behavior rather than explicit generated settings; runtime authentication was not tested.
- Restic password can be empty. Secret files do receive mode 0600 and are ignored by Git. SQL credentials are generated, but setup is interactive-only and has no failure checks, explicit EULA consent, nonempty secret validation or documented unattended interface. Subsequent setup skips existing files, including an invalid backup secret file.
- Backup and Traefik mount the Docker socket read-only. A read-only socket bind does not restrict Docker API operations. Backup can discover containers beyond this stack, so a shared-daemon backup probe must prove project scoping before use. Traefik has no `exposedByDefault=false`, hardcodes network `minecraft` although Compose normally project-prefixes it, and refers to an `auth` middleware with no definition in the template. These are configuration findings, not reproduced web runtime failures.
- Images mostly use unpinned defaults; Traefik pins v2.3. No runtime verification of image compatibility, downloads, readiness, backup behavior or generated configuration has happened. The README's claim of latest builds disagrees with the pinned Minecraft version.
- `cleanup.sh` deletes local environment, secrets and server/database/RCON data without confirmation. `update.sh` pulls, commits and pushes automatically. Neither was executed. `restart.sh` requires a plugin command. The README and SQL secret filename disagree in places. Keep destructive maintenance outside validation.

## Outside-in validation contract for implementation

This is a proposed acceptance contract, not a claim that the baseline passes it. Use the final template's documented public scripts and inspect actual server behavior. Keep one small bounded harness rather than tests that mirror implementation details.

1. **Fresh setup and negative cases.** Start from tracked files with no generated data. Supply explicit unattended inputs, including EULA consent, chosen supported Minecraft version and strong secrets. Setup and config validation must run with stdin closed, fail clearly on missing EULA consent, invalid port or memory, missing or empty required secrets, and unavailable Docker. Failed setup must not launch services or announce success. Run setup twice and verify credentials and existing world data remain unchanged. Generated secrets must be ignored by Git and mode 0600; logs must redact them. Configuration validation must reject contradictory forwarding/authentication settings. Production must not accept offline mode as its default.
2. **Isolation and resource budget.** Allocate a unique Compose project and disposable data, backup and restore volumes or directories. Explicitly select only required services. Publish only the tested game entrypoint on `127.0.0.1` at an available high port, or use an internal client container. Do not publish DB, backend game TCP, RCON or JDWP in proxy mode. Do not mount the Docker socket for the harness; if the final backup implementation requires it, establish and inspect strict project targeting before invoking it. Record architecture and available disk, use ARM64-compatible images, modest memory and small view/simulation distance, and run standalone and proxy phases sequentially. Capture failed pulls as infrastructure blockers, not application passes.
3. **Standalone Paper.** Launch Paper without proxy or DB, using the selected version. Wait with a deadline for usable RCON and a Minecraft status response. Assert actual version and a deliberately chosen MOTD, execute `list` and `version` through the public command helper with non-TTY execution, and reject an incorrect RCON password. Verify generated server properties keep online authentication and both proxy forwarding modes disabled. Status and RCON prove service readiness; they do not prove player login.
4. **Velocity forwarding and login.** Launch Velocity and Paper without DB. Verify effective runtime `velocity.toml`, Paper proxy config and Spigot settings, a shared nonempty modern forwarding secret, the correct backend address, and disabled legacy Bungee forwarding. Query Minecraft status through Velocity. For an automated actual login, use a separate isolated test override that disables online authentication only for this test and configures the matching Paper proxy authentication expectation while retaining modern forwarding and the secret. Use a protocol-compatible client such as a disposable Bun-installed Minecraft client package. Require it to reach play/spawn, then prove its unique username is present in backend RCON `list` and correlate backend join logs. A status response or proxy-only connection is insufficient. With a wrong forwarding secret, login must fail. A client on the private network must also fail direct backend login without forwarding. No backend port is published. Restore the production configuration and verify online authentication remains enabled; account-authenticated production login remains a separate manual check if no account credentials are supplied.
5. **Configuration and persistence.** Set a unique MOTD and confirm it in status, then create persistent world state via RCON, for example a scoreboard objective and a score of 42 for a test holder. Flush saves, recreate the Paper container while retaining its volume, and verify the same score through RCON. Recreate the proxy as well and repeat status and isolated client login. Confirm mounted plugin/config changes reach generated runtime files without overwriting saved world state or exposing secrets.
6. **Backup and disposable restore.** Trigger the same job used by the scheduled backup through the documented noninteractive manual command. Verify its schedule exists, its snapshot is new, and logs show successful flush plus saving restored after backup. Verify that a failed backup also restores saving. Mutate the persistent score after the snapshot. Restore that snapshot into a separate disposable volume, start a separate Paper instance against it, and prove the pre-backup score through RCON. Listing a snapshot alone does not prove restore. Never restore over the source world, never use retention cleanup against unrelated repositories, and never run a socket-discovering backup job without proven project scope.
7. **Optional DB.** The default standalone and proxy cases must succeed with DB disabled and no SQL credentials. Enable only the optional DB service, wait for readiness, authenticate with generated application credentials, create/read a temporary row and verify it persists through DB container recreation. Reject wrong credentials and verify no host DB port. Include SQL backup and disposable restore only if the final implementation promises DB backup.
8. **Failure evidence and cleanup.** Every command and readiness wait has a GNU timeout and a recorded exit code. Capture Compose service state, logs, status response, RCON output and client result before cleanup. Cleanup only this project and its named test resources, including restored data and client dependencies. After timed-out Docker operations, check again for delayed creation and remove exact owned names. Record final resource absence and compare the unrelated container ID inventory without modifying those containers. Never prune Docker or call the template's destructive `cleanup.sh`. Preserve logs after failure and report the exact stage, command and reason.

## Resolution

The baseline is blocked before a production launch by the missing legacy Compose executable and duplicate YAML key. EOF setup gives false success with an empty backup secret. Docker inspection works on this ARM64 shared host, but the bounded tiny-container execution did not reach its command. The next worker has a concrete validation contract and durable failure evidence. Minecraft runtime, Velocity login, persistence, backup restore and DB behavior remain untested until implementation resolves startup and isolation. This ticket is complete as a baseline investigation.
