# Version and deployment decisions

Verified 2026-10-01 UTC. The research decision is adopted here for the maintained template; raw responses remain in the research ticket's evidence directory.

The default is Paper 26.2 build 129, the latest stable Paper build. Minecraft's current release is 26.3. Paper 26.3 builds are beta, so `setup --distribution vanilla` selects the released Mojang 26.3 server. Both use Java 25. The exact software and multi-platform image pins are in [versions.env](../versions.env). [Mojang release manifest](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json), [Paper build API](https://fill.papermc.io/v3/projects/paper/versions/26.2/builds/129), [Paper 26.3 channels](https://fill.papermc.io/v3/projects/paper/versions/26.3/builds), [Java requirements](https://docs.papermc.io/paper/getting-started/).

Velocity 4.2.1-SNAPSHOT build 36 is marked STABLE by Paper's API. The suffix alone does not identify the release channel. Modern forwarding uses a shared random secret, authenticates at the proxy, and keeps the backend unpublished. A standalone server authenticates directly. [Velocity build API](https://fill.papermc.io/v3/projects/velocity/versions/4.2.1-SNAPSHOT/builds/36), [forwarding configuration](https://docs.papermc.io/velocity/player-information-forwarding/), [backend protection](https://docs.papermc.io/velocity/security/).

The server and proxy wrappers are pinned to their Java 25 release images. Backup uses the maintained itzg sidecar with restic, internal RCON, save flush coordination and interval scheduling. MariaDB 12.3.3 is optional. NGINX serves optional static files over loopback. Each image digest identifies an index with Linux amd64 and arm64 manifests, verified in research. Runtime proof in [validation.md](validation.md) states which architecture actually ran. [Server publisher](https://github.com/itzg/docker-minecraft-server/tree/2026.9.2), [proxy publisher](https://github.com/itzg/docker-bungeecord/tree/2026.9.2), [backup implementation](https://github.com/itzg/docker-mc-backup/blob/2026.9.3/scripts/opt/backup-loop.sh), [MariaDB LTS](https://mariadb.org/mariadb-server-12-3-lts-released/).

Retired template wiring includes Waterfall, the stale RCON web UI, public phpMyAdmin and JDWP, the old socket-discovering backup image, and Docker socket based Traefik discovery. Maintained plugins can be installed explicitly, but their presence is not a compatibility guarantee. The replacement paths and upgrade precautions are in [migration.md](migration.md). [Waterfall retirement](https://papermc.io/news/announcing-the-end-of-life-of-waterfall/), [Docker socket risks](https://docs.docker.com/engine/security/), [Docker Engine 28 loopback fix](https://docs.docker.com/engine/network/port-publishing/).

Run `scripts/check-versions` to verify the pinned release metadata and image indexes again. Updates require reviewing the pin changes and repeating full runtime and restore validation. Floating `latest` tags and automatic software upgrades are excluded.

## Maintained integration decisions after independent review

The pinned backup loop performs mutating `save-on` readiness before acquiring its shared lock. Two independent runtime reviews reproduced saving being re-enabled while another job held the lock. `Dockerfile.backup` derives from the pinned upstream image and changes only that readiness seam to `list`, with exact build-time checks. Full validation overlaps two real Restic jobs and checks save-off remains active until the first is released.

CI uses official [checkout v7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1) at `3d3c42e5aac5ba805825da76410c181273ba90b1` and [upload-artifact v7.0.1](https://github.com/actions/upload-artifact/releases/tag/v7.0.1) at `043fb46d1a93c77aae656e7c1c64a875d1fc6a0a`. Publisher release APIs and peeled tag commits were checked on 2026-10-01. Checkout requires Node24-capable runners, minimum runner2.327.1; authenticated Git within Docker actions needs2.329.0. This repository uses GitHub-hosted Ubuntu runners and normal `pull_request`, avoiding the v7 unsafe-fork `pull_request_target` opt-in. Upload jobs use separate immutable artifact names, and the GitHub.com service supports the action. Runtime validation runs on PRs as well as explicit workflow dispatch.
