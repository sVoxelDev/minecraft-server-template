# Migrating the 1.17 template

Keep the old checkout and deployment intact. Take and restore-test a complete offline backup of its world, database, plugin data, configuration and secrets. Build the new template in a separate checkout. Setup refuses detected legacy server or secret paths and does not migrate them.

A 1.17 world upgrade is a one-way data-format change. Follow Paper's upgrade guidance and each plugin's supported upgrade path. Rehearse with copies, including any required intermediate versions. Check world generation, player inventories, permissions, plugin behavior and SQL migrations before moving traffic. Retain a rollback copy of the old deployment; newer world data cannot safely be opened by 1.17. [Paper update guidance](https://docs.papermc.io/paper/updating/).

## Old paths and replacements

| Old paths | Migration action |
| --- | --- |
| `servers/`, `servers/main/`, `servers/proxy/`, `servers/minimal/server/`, `servers/minimal/database/`, `minimal/`, `worlds/` | Locate actual world and plugin data. Copy only a stopped, backed-up rehearsal world into a new `data/server/`; keep old production untouched. |
| `database/`, `mysql.env`, `sql.secrets.env`, `configs/my.cnf` | Export SQL with the old server's supported dump tool. Review compatibility before importing into optional MariaDB. Never copy a running old database directory into MariaDB 12.3. |
| `globals.env`, `server-properties.env`, `ports.env`, `.env` | Replace with explicit setup options and reviewed generated `.state/settings.env`. Remove inherited offline authentication and debug options. |
| `rcon.env`, `rcon.secrets.env`, `rcon/` | Retire the public RCON web UI. Use the new internal `scripts/minecraft command` and its freshly generated secret. |
| `backup.env`, `backup.secrets.env`, `backup/`, `configs/excludes.txt` | Keep old repositories and passwords for recovery. Initialize the new restic repository and test a new restore. The new sidecar targets only this server and has no Docker socket. |
| `configs/main/paper.yml`, `configs/main/spigot.yml`, `configs/main/bukkit.yml` | Rebuild current configs under `configs/server/`. Paper global/world settings changed since 1.17; copying old `paper.yml` is insufficient. Preserve modern forwarding generated by network setup. |
| `configs/main/commands.yml`, `help.yml`, `permissions.yml`, `wepif.yml`, `excludes.txt`, `server-icon.png` | Review custom commands/permissions and plugin support, then copy useful files explicitly. Do not carry obsolete exclude lists. |
| `configs/proxy/config.yml`, `waterfall.yml`, `modules.yml`, `locations.yml`, `excludes.txt`, `server-icon.png` | Waterfall is retired. Rebuild routing in `.state/velocity.toml`. Bungee/Waterfall plugins require Velocity replacements. |
| `plugins/`, `plugins/Plan/config.yml`, `plugins/dynmap/configuration.txt` | Replace jars with current compatible releases under `plugins/server/`. Rebuild plugin configs from those releases. Old configs may contain SQL passwords or obsolete paths. Mapping output previously under `servers/main/plugins/dynmap/web/` or `servers/minimal/server/plugins/dynmap/web/` must be regenerated by the current plugin. |
| `proxy-plugins/`, `proxy-plugins/Plan/config.yml` | Install compatible Velocity plugins under `plugins/proxy/`; rebuild their configs and database settings. |
| `dynmap/main/` including `js/`, `css/`, `images/`, `standalone/`, PHP/ASPX and generated config files | Discard the vendored old web client. Use assets generated by a current compatible mapping plugin. Keep admin access private. |
| `downloads/conf/default.conf`, `downloads/files/`, `web/` | Move approved static downloads into new `web/`. The optional NGINX profile binds loopback and adds no PHP execution. |
| `schematics/` | Preserve copies and install them in the path expected by the current editing plugin. |
| All `docker-compose.*.yml` fragments: `main`, `minimal`, `proxy`, `db`, `backup`, `dynmap`, `download`, `rcon`, `traefik` | Replace with `compose.yaml` and explicit profiles. Review external HTTPS routing separately; public admin, debug and Docker socket mounts are removed. |
| `init.sh`, `dc.sh`, `minimal.sh`, `cmd.sh`, `console.sh`, `backup.sh`, `restart.sh` | Use `scripts/minecraft` setup/start/compose/command/backup/stop. Interactive console is available through internal RCON commands. |
| `debug.sh`, `cleanup.sh`, `update.sh`, `zip-plugins.sh`, `scripts/prep-env.sh`, `scripts/utils.sh`, `lib/scripts/build.local.gradle` | Retired unsafe or stale helpers. Use explicit reviewed maintenance and your plugin project's build. No automatic data deletion, Git push or public JVM debug port remains. |

Old secret files stay sensitive. The ignore rules retain legacy runtime and secret paths to prevent accidental commits during migration, as well as the new generated paths. Keep migration copies outside Git. Update clients, reverse proxy routes and scheduled external jobs only after the replacement passes your restore and login rehearsal. The template's disposable tests certify its own server flow, not your old plugins or production migration.
